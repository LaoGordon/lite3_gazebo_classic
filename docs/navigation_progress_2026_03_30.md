# 导航集成联调进展 (2026-03-30)

## 今日核心改动与解决的问题

今天的工作主要围绕**“完善基于 FAST-LIVO2 的单层 2D 降维地图（floor_mapper）”**以及**“解决局部地图的视野遮挡与闪烁问题”**展开。

### 1. 解决 `floor_mapper` 地图闪烁与残影问题
- **现象**：之前基于单帧激光雷达（0.1s）直接投影的 2D `OccupancyGrid` 覆盖率极低，导致在 RViz 和 Nav2 Costmap 中地图表现为断断续续的黑线且剧烈闪烁。同时，过去简单的累加方式无法清理动态障碍物（如行走的人留下的尾迹）。
- **根因及方案**：
  - 代码层面缺少时域滤波。
  - **修改内容**：我们在 `floor_mapper_node.cpp` 中引入了基于 `std::deque` 的**点云历史缓冲队列机制**。
  - **效果**：新增 `history_duration` 参数（默认 1.5 秒）。该节点现在会将过去 1.5 秒内的所有局部点云进行拼合并重新投影，且会自动挤出超过 1.5 秒的老旧点云。成功实现了“稠密、不闪烁、且无死点残影”的完美局部探照灯效果。

### 2. 解决 FAST-LIVO2 彩色视场遮挡（局部视野受限）问题
- **现象**：生成的 2D 地图只在机器狗正前方产生，左右和后方的雷达点云全部丢失。
- **根因及方案**：
  - FAST-LIVO2 的视觉渲染代码（`LIVMapper.cpp`）里，在 `img_en=1` （启用视觉）时，会强制剔除那些无法映射到相机画面内（即相机背后或 FOV 之外）的点。
  - 我们不能关闭视觉着色（否则丧失 LIVO 优势），因此采用**数据解耦**策略。
  - **修改内容**：在 `FAST-LIVO2` 的源码中（子模块），新增了一个名为 `/cloud_registered_lidar` 的话题，提取配准后但**未经过色彩FOV裁剪**的 360 度全向点云；同时在主仓库 `fastlivo_nav_bridge/bridge.launch.py` 中将输入话题无缝切换到此新话题。
  - **效果**：在不增加计算负担、保留前方彩色点云视觉特性的基础上，完美剥离出了稳健的 360 度纯几何点云供后端导航层使用。

### 3. 子仓库（Submodule）全面迁移与清理
- **内容**：将 `.gitmodules` 中所有依赖失效小号 `oldgorden` 的链接全部替换为你的主账号 `LaoGordon`。

## 存在的架构隐患与遗留问题

### 核心矛盾：局部图当成了全局图喂给了 Nav2
- **发现的错配**：目前 `nav2_params.yaml` 中，`global_costmap` 直接订阅了 `floor_mapper` 的输出（被配置为 `StaticLayer`）。
- **问题表现**：因为 `floor_mapper` 机制上是一个“仅记忆周边 20x20m、时效 1.5s 的动感探照灯”。如果规划目标在视野外（或者隔了墙），全局规划器（Global Planner）因为没有远处的历史静态结构输入，就会把未知区域当成坦途，直接画一条穿墙的直线，导致机器狗后续运动受困和反复打转。

## 下一步工作建议 (Next Steps)

明确：**坚决不将 `floor_mapper` 改为耗费算力的全局光线追踪建图器。它应当回归本职——作为 Local Costmap 的动态避障（Obstacle Layer）输入。**

为了实现真正的超视距全局导航，我们要走向**“静态全局建图 + 动态局部避障的双层架构”**，并将为最终的跨楼层（拓扑图切换）打下基础架构。

**下一步具体的执行计划：**

1. **配置修正（修复遗留 Bug）**
   - 修改 `nav2_params.yaml`。取消 Global Costmap 对 `/floor_map` 的静态层订阅。将 `/floor_map` 移入 `local_costmap`，正式成为局部动态避障层。
2. **走通“离线静态地图 (Static Map Server) 制备链路”**
   - 编写或引入一种离线（offline）降维机制。
   - 我们需要开着机器狗跑一圈，让 FAST-LIVO2 生成一次全局 3D PCD 点云并落盘保存。
   - 对保存好的全局 PCD 进行 Z 轴切片（比如截取 0~1m 高度），投影并生成一张全局静态的 2D `.pgm` 图与 `.yaml`（`floor_1`）。
3. **走通基于 Map Server 的全局规划**
   - 在 `navigation_bringup` 中新增拉起 `nav2_map_server` 与 `nav2_amcl` (或让 LIVO 通过先验地图直接代偿 AMCL 功能)。
   - 让全局规划器拥有“上帝视角”的蓝图，能规划出过弯或穿走廊的合理路径。
